# ระบบหารบิลผ่าน LINE

บอท LINE สำหรับกลุ่มเพื่อน ใช้บันทึกบิล หารค่าอาหาร สร้าง QR พร้อมเพย์ของแต่ละคน ตรวจสลิปอัตโนมัติ และแจ้งเตือนผู้ที่ยังไม่ชำระในกลุ่มทุกวัน 18:00 น.

## ภาพรวม

```
กลุ่ม LINE ──(webhook)──▶ server (Node.js) ──▶ Supabase (Postgres + Storage)
     ▲                         │   ▲                 
     │ ข้อความ/แท็ก (textV2)    │   └── เว็บ React (LIFF) เปิดจากลิงก์ในกลุ่ม
     └─────────────────────────┘
                               └──▶ บริการตรวจสลิป (EasySlip หรือ SlipOK)
ตัวตั้งเวลา (GitHub Actions / cron) ──▶ POST /cron/remind ทุกวัน 18:00 น.
```

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `server/` | บอท LINE, API ของเว็บ, ตรวจสลิป, ทวงรายวัน (Node.js 20+ ไม่มี dependency ภายนอก) |
| `web/` | เว็บ React + Vite + TypeScript เปิดผ่าน LIFF |
| `shared/` | โค้ดคำนวณยอดและสร้าง QR พร้อมเพย์ ใช้ร่วมกันทั้งสองฝั่ง |
| `supabase/schema.sql` | โครงสร้างฐานข้อมูล |

## การทำงานในกลุ่ม

1. เชิญบอทเข้ากลุ่ม บอทจะส่งลิงก์เว็บของกลุ่มนั้น
2. สมาชิกพิมพ์ข้อความใดก็ได้ในกลุ่มหนึ่งครั้ง เพื่อให้ระบบรู้จักชื่อ (ข้อจำกัดของ LINE: บัญชีทั่วไปดึงรายชื่อทั้งกลุ่มไม่ได้)
3. ผู้ที่จ่ายบิลไปก่อนเปิดเว็บ > สร้างบิล > ใส่รายการ ราคา ผู้ร่วมจ่ายของแต่ละรายการ เลขพร้อมเพย์ และรูปใบเสร็จ
   - เลือกผู้ร่วมจ่ายได้เร็วจาก "ชุดรายชื่อที่ใช้บ่อย" (บันทึกไว้ใช้ทั้งกลุ่ม) หรือ "รายชื่อจากบิลล่าสุด" แล้วค่อยเพิ่ม/ลดทีละคน
4. บอทโพสต์สรุปในกลุ่มและแท็กทุกคนพร้อมยอดที่ต้องจ่าย
5. แต่ละคนเปิดเว็บ ดู QR ของตัวเอง (ยอดเงินฝังใน QR แล้ว) โอนเงิน แล้วส่งรูปสลิปในกลุ่ม
6. บอทตรวจสลิป:
   - อ่านสลิปผ่านบริการตรวจสลิป → เป็นสลิปจริง
   - เลขอ้างอิงไม่ซ้ำ (เก็บใน `payments.trans_ref` แบบ unique)
   - บัญชีผู้รับตรงกับผู้รับเงินของบิล (เทียบเลขพร้อมเพย์/เลขบัญชี/ชื่อบัญชี กับเลขที่ถูกปิดบางส่วนในสลิป)
   - ยอดตรงกับบิลใดบิลหนึ่ง หรือยอดรวมทุกบิลที่ค้างผู้รับคนเดียวกัน (โอนเกินได้ไม่เกิน `AMOUNT_OVERPAY_TOLERANCE` บาท)
   - ผ่าน: ติ๊กชำระแล้ว เก็บรูปสลิป แล้วตอบในกลุ่ม / ไม่ผ่าน: แท็กพร้อมแจ้งสาเหตุ
   - รูปทั่วไปที่ไม่ใช่สลิป หรือส่งโดยคนที่ไม่มียอดค้าง บอทจะไม่ตอบ
7. ทุกวัน 18:00 น. บอทแท็กทุกคนที่ยังค้าง (ส่งวันละ 1 ครั้งต่อกลุ่ม ไม่ส่งถ้าไม่มีใครค้าง)

หน้า "สรุปยอด" ดูได้ 2 แบบ: **รายคน** (แต่ละคนค้างร้านไหน วันไหน ให้ใคร) และ **รายร้าน** (แต่ละร้าน ไปกี่ครั้ง แต่ละครั้งมีใครบ้าง ใครจ่ายแล้ว) กรองช่วงวันที่ ค้นหา และเลือกแสดงเฉพาะที่ยังค้างได้

คำสั่งในกลุ่ม: `เมนู` ขอลิงก์เว็บ, `ยอดค้าง` ดูยอดค้างทั้งหมด (ตอบด้วย reply ไม่เสียโควตา)

### โควตาข้อความ
ข้อความที่บอทตอบหลังมีคนส่งข้อความ/สลิป ใช้ reply ซึ่งไม่นับโควตา ส่วนที่นับโควตา (push) มีแค่ ข้อความทวง 18:00 และประกาศบิลใหม่
LINE นับ push 1 ครั้งในกลุ่ม = จำนวนสมาชิกในกลุ่ม เช่น กลุ่ม 6 คน ทวง 1 ครั้ง = 6 ข้อความ
ถ้าโควตาฟรีไม่พอ ปิดการประกาศบิลใหม่ได้ด้วย `ANNOUNCE_NEW_BILL=false`

## ขั้นตอนติดตั้ง

### 1. Supabase
1. สร้างโปรเจกต์ที่ https://supabase.com
2. เมนู SQL Editor > วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ > Run (จะสร้างตาราง ฟังก์ชัน และ bucket `bill-files` แบบส่วนตัว)
   - ถ้าเคยรัน schema.sql เวอร์ชันแรกไปแล้ว ให้รัน `supabase/migrations/002_member_presets.sql` เพิ่ม (ตารางชุดรายชื่อที่ใช้บ่อย)
3. Project Settings > API: คัดลอก `Project URL` และ `service_role` key

### 2. LINE Official Account + Messaging API
1. สร้าง LINE Official Account และเปิด Messaging API (https://developers.line.biz/console/)
2. ใน LINE Official Account Manager > ตั้งค่า > การตอบกลับ: เปิด **Webhook** ปิด **ข้อความตอบกลับอัตโนมัติ**
3. ตั้งค่าบัญชี: เปิด **อนุญาตให้บอทเข้าร่วมแชทกลุ่ม**
4. ใน LINE Developers > Messaging API channel: คัดลอก `Channel secret` และออก `Channel access token (long-lived)`
5. ตั้ง Webhook URL เป็น `https://<โดเมนของคุณ>/webhook` แล้วเปิด Use webhook

### 3. LINE Login + LIFF
1. สร้าง **LINE Login channel ใน Provider เดียวกับ Messaging API channel** (สำคัญ: userId ของผู้ใช้ต่างกันในแต่ละ Provider ถ้าคนละ Provider ระบบจะจับคู่สมาชิกไม่ได้)
2. แท็บ LIFF > Add: Size = Full, Endpoint URL = `https://<โดเมนของคุณ>/`, Scopes = `openid`, `profile`
3. คัดลอก `LIFF ID` และ `Channel ID` ของ LINE Login channel

### 4. บริการตรวจสลิป
เลือกอย่างใดอย่างหนึ่ง
- **EasySlip** (ค่าเริ่มต้น): สมัครที่ https://easyslip.com นำ API key ใส่ `EASYSLIP_API_KEY`
- **SlipOK**: สมัครที่ https://slipok.com ใส่ `SLIP_PROVIDER=slipok`, `SLIPOK_BRANCH_ID`, `SLIPOK_API_KEY`

ทั้งสองเจ้ามีโควตาฟรี/แพ็กเกจรายเดือน ควรตรวจสอบราคาปัจจุบันก่อนใช้งาน
ระบบรองรับทั้ง EasySlip v1 และ v2 (เปลี่ยน endpoint ได้ที่ `EASYSLIP_URL`)

### 5. ตั้งค่าและรัน
```bash
cp server/.env.example server/.env   # แล้วกรอกค่าทั้งหมด
cd web && npm install && npm run build && cd ..
cd server && npm start
```
เซิร์ฟเวอร์ตัวเดียวให้บริการทั้ง เว็บ (`/`), API (`/api/*`), webhook (`/webhook`) และตัวทวง (`/cron/remind`)

### 6. Deploy
ใช้ `Dockerfile` ที่ root ได้กับผู้ให้บริการที่รองรับ Docker เช่น Render, Railway, Fly.io, Google Cloud Run
- ตั้งค่า environment ตาม `server/.env.example`
- ต้องเป็น HTTPS (LINE บังคับสำหรับ webhook และ LIFF)

### 7. ตั้งเวลาทวง 18:00 น.
เลือกวิธีใดวิธีหนึ่ง
- **GitHub Actions** (แนะนำเมื่อโฮสต์อาจหลับ): ใช้ไฟล์ `.github/workflows/remind.yml` ตั้ง Secrets `APP_URL` และ `CRON_SECRET` (GitHub อาจเรียกช้ากว่ากำหนดหลายนาที)
- **cron-job.org** หรือบริการ cron อื่น: เรียก `POST https://<โดเมน>/cron/remind` พร้อม header `x-cron-secret: <CRON_SECRET>` ทุกวัน 18:00 (Asia/Bangkok)
- **ภายในเซิร์ฟเวอร์**: `ENABLE_INTERNAL_CRON=true` (ใช้ได้เมื่อเซิร์ฟเวอร์เปิดตลอดเวลา)

ระบบกันการทวงซ้ำวันละครั้งต่อกลุ่มด้วยตาราง `reminder_runs` จึงเปิดหลายวิธีพร้อมกันได้โดยไม่ส่งซ้ำ

## พัฒนาและทดสอบ

```bash
# ทดสอบตรรกะฝั่งเซิร์ฟเวอร์ (คำนวณยอด, QR พร้อมเพย์, จับคู่สลิป, ข้อความ, ลายเซ็น webhook)
cd server && npm test

# ดูหน้าเว็บด้วยข้อมูลตัวอย่าง ไม่ต้องต่อ LINE/เซิร์ฟเวอร์
cd web && npm install && npm run dev:mock
# เปิด http://localhost:5173  (เพิ่ม ?mockError=session หรือ ?mockError=bills เพื่อดูหน้าแจ้งข้อผิดพลาด)

# ทดสอบเว็บกับเซิร์ฟเวอร์จริงในเครื่องโดยไม่ผ่าน LIFF
# ตั้ง DEV_AUTH_USER_ID=<LINE userId ของคุณ> ใน server/.env แล้วเปิด http://localhost:5173/?g=<access_key ในตาราง groups>
```

## ความปลอดภัย
- webhook ตรวจลายเซ็น `x-line-signature` ทุกครั้ง
- เว็บส่ง LIFF ID token ไปให้เซิร์ฟเวอร์ตรวจกับ LINE และเซิร์ฟเวอร์ตรวจว่าผู้ใช้เป็นสมาชิกของกลุ่มนั้นจริง
- ลิงก์เว็บใช้รหัสสุ่ม (`access_key`) แทน groupId จริง
- ฐานข้อมูลเปิด Row Level Security และไม่มี policy สาธารณะ เซิร์ฟเวอร์เท่านั้นที่เข้าถึงได้ด้วย service_role key
- รูปใบเสร็จ/สลิปเก็บใน bucket ส่วนตัว เปิดดูผ่านลิงก์ชั่วคราว 1 ชั่วโมง

## ข้อจำกัดที่ควรทราบ
- สมาชิกต้องพิมพ์ในกลุ่มอย่างน้อยหนึ่งครั้งก่อนจึงจะถูกเลือกในบิลได้ (ยกเว้นบัญชี Verified/Premium ที่ปุ่ม "อัปเดตรายชื่อจากกลุ่ม" ดึงได้ทั้งกลุ่ม)
- การยืนยันผู้รับเงินอาศัยข้อมูลที่ธนาคารแสดงในสลิป ซึ่งถูกปิดบางส่วน หากผู้รับเงินค้างกับหลายคนและสลิปแสดงเฉพาะเลขบัญชี ผู้รับเงินควรกรอกเลขบัญชีและชื่อบัญชีในหน้า "บัญชีรับเงิน"
